# Drevortex 官网重建方案索引

本目录用于冻结本次官网重启项目的全部前置方案。

在你明确批准前，后续不会开始正式编码。进入开发阶段后，所有实现必须严格遵循本目录文档，不得临时改栈、改架构、改页面信息结构。

## 文档清单

1. `00-旧站扫描报告.md`
   - 旧官网副本的目录结构、页面结构、动效清单、技术债与迁移风险。
2. `01-重建总方案.md`
   - 本次重建的目标、原则、推荐技术栈、目标信息架构、仓库结构与重建策略。
3. `02-产品需求文档.md`
   - 面向产品与界面的正式需求文档，约束页面范围、核心模块、交互要求与设计原则。
4. `03-技术架构方案.md`
   - 面向研发的正式技术架构文档，包含前后端、数据库、接口、部署、安全与性能方案。
5. `04-实施计划与验收标准.md`
   - 分阶段施工顺序、里程碑、风险处理、测试范围与验收口径。

## 当前冻结结论

- 前端框架固定为 React 体系，推荐落地为 `Next.js + React + TypeScript`。
- 项目形态固定为“前端站点 + 后端 API + PostgreSQL 数据库 + 管理后台能力预留”。
- 页面范围固定为旧站现有 5 个公开页面的高保真重建，不减少页面，不改主布局，不删核心视觉记忆点。
- 旧站首页的重动效不做原样搬运，而是做“视觉等价、性能重写、结构组件化”的工程化重构。
- 开发顺序固定为“先设计系统与页面骨架，再后端与数据库，再真实表单链路，再后台内容管理”。

## 开发前约束

- 未经批准，不进入编码阶段。
- 真正开始编码后，优先保证页面结构、视觉层级、动画节奏与交互路径与旧站一致。
- 不允许把兜底逻辑硬编码进展示层模板。
- 所有内容数据源必须逐步从硬编码迁移到受控配置或数据库，不再保留假表单和假数据链路。
