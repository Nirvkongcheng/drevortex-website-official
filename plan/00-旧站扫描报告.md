## 5. 旧站技术债

### 5.1 结构债

- 每个页面各自维护 `index.html / index.css / index.js`，完全没有组件复用。
- 子页重复逻辑没有抽象，维护成本极高。
- 公共样式 token 不完整，子页存在未定义 CSS 变量引用。

### 5.2 性能债

- 首页同时存在多套基于 `scroll`、`requestAnimationFrame`、Canvas、DOM 动画的逻辑。
- 动画基本依赖直接操作 DOM 和内联样式，难以做节流与状态治理。
- 外链字体、图标、图片与图床资源过多，首屏稳定性差。

### 5.3 数据债

- 联系表单不接后端，只做前端模拟。
- 客户数、满意度、案例数、版权年份等均为硬编码。
- 多个链接为 `#`，缺乏真实去向。

### 5.4 内容债

- 存在明显历史残留文案与模板污染。
- 地址、电话等联系信息仍带占位符。
- 案例与图片来源混杂，版权与真实性不可控。

## 6. 重建时必须解决的问题

1. 不能再保留假表单链路，必须接入真实后端与数据库。
2. 不能再让页面结构依赖复制粘贴式 CSS/JS。
3. 不能把复杂动效全部压在首屏同步执行。
4. 不能继续依赖第三方图床和不可控外链资源。
5. 不能继续把页面内容、案例、站点配置硬编码在模板里。

## 7. 迁移策略结论

### 7.1 必须 1:1 保留的内容

- 页面数量
- 页面主布局
- 视觉层级
- 主色与品牌识别
- 首页关键动效的观感与节奏
- 重要版块的出现顺序

### 7.2 必须重写的内容

- 所有前端结构代码
- 所有路由组织方式
- 所有交互状态管理
- 联系表单链路
- 内容数据管理方式
- 样式系统与设计 token
- 图片与媒体资源组织方式

### 7.3 不建议照搬的内容

- 首页全部逐帧 DOM 操作
- 文本选择修复脚本
- 所有外链图片与图床
- 伪造的验证码倒计时行为
- 重复子页脚本

## 8. 重建基线

本项目不做“修旧站”，而是做“在新架构中高保真重建旧站表现”。

工程目标不是把旧代码搬过去，而是把旧站表现拆成：

- 设计 token
- 页面骨架
- 组件层
- 动效层
- 数据层
- API 层

然后在 React 全新技术栈中重新实现。
