# 实施计划与验收标准

## 1. 实施总原则

- 先冻结方案，再开始编码。
- 先搭基础架构，再做页面高保真迁移。
- 先完成公共系统，再做首页复杂动效。
- 先打通真实数据链路，再做后台管理深化。
- 每一阶段完成后都要可运行、可验证、可回滚。

## 2. 严格施工顺序

### 阶段 0：方案冻结

交付物：

- 旧站扫描报告
- 重建总方案
- 产品需求文档
- 技术架构方案
- 实施与验收文档

验收标准：

- 文档边界清晰
- 技术栈、页面范围、数据库范围、实施顺序已冻结

### 阶段 1：项目初始化

交付物：

- `pnpm workspace` 单仓结构
- `apps/web`
- `apps/api`
- 共享包基础结构
- ESLint / TypeScript / 格式化规则
- 环境变量模板

验收标准：

- 前后端都能启动
- 仓库结构清晰
- 基础 lint 与 typecheck 可运行

### 阶段 2：设计系统与公共骨架

交付物：

- 设计 token
- 主题系统
- 公共布局
- Header / Footer
- 通用容器、标题、按钮、卡片
- Reveal 动画基础能力

验收标准：

- 深浅主题切换可用
- 导航与页脚 1:1 对齐旧站气质
- 子页公共结构可以复用

### 阶段 3：公开页面静态骨架迁移

交付物：

- 5 个公开页面的静态结构
- 页面 SEO 元信息骨架
- 路由与导航可用

验收标准：

- 所有页面可访问
- 页面主布局、顺序、层级与旧站一致
- 仍允许部分动效未接入，但结构必须齐全

### 阶段 4：首页高保真动效重写

交付物：

- 开场序列重写
- Hero 动效重写
- 价值数字与滚动触发动画
- 业务翻页展示重写
- 服务弧形展示重写
- 固定 CTA 与 hover 微交互

验收标准：

- 视觉观感接近旧站或优于旧站
- 动画由模块化 hooks / controllers 驱动
- 不存在巨型单文件脚本和无法治理的滚动逻辑

### 阶段 5：后端与数据库

交付物：

- PostgreSQL 数据模型
- Prisma schema
- NestJS 模块
- 公共读取 API
- 联系表单 API
- 基础鉴权 API

验收标准：

- 数据库迁移可执行
- API 契约稳定
- 联系表单可真实写库

### 阶段 6：后台管理

交付物：

- 管理员登录
- 站点配置管理
- 首页内容管理
- 关于/服务/案例管理
- 留资记录查看与状态更新

验收标准：

- 管理员可以登录
- 内容修改后前台能读取到最新数据
- 留资记录可在后台查询

### 阶段 7：测试、优化与发布

交付物：

- 关键流程测试
- 性能优化
- SEO 检查
- 安全基线检查
- 部署配置

验收标准：

- 公开页面核心流程跑通
- Lighthouse 与 Web Vitals 达标
- 生产构建可部署

## 3. 视觉验收标准

- 页面模块顺序不能乱。
- 主导航、Hero、服务区、案例区、联系区的版式记忆点必须保留。
- 首页开场不允许被简化成普通淡入。
- 深色主题必须作为主视觉基准成立。
- 卡片、边框、阴影、蓝色强调色、细噪点与微光层必须统一。

## 4. 工程验收标准

- 组件必须可复用，子页不能复制粘贴逻辑。
- 动效系统必须分层，禁止单文件堆积数百行混杂逻辑。
- 内容与数据不能继续硬编码散落在页面模板中。
- 联系表单必须是真实 API，不接受前端模拟成功。
- 数据库 schema、接口定义、页面结构必须一致。

## 5. 性能验收标准

- 首页首屏必须控制同步执行任务数量。
- 图片、字体、动画资源都要有加载策略。
- 移动端复杂动效允许降级，但不能破坏信息结构。
- `prefers-reduced-motion` 下必须有可用降级。

## 6. 安全验收标准

- 管理后台未登录不可访问受保护页面。
- 后台接口必须鉴权。
- 联系接口必须有限流与参数校验。
- 不允许在前端暴露敏感配置。

## 7. 风险与应对

### 风险 1：首页动效还原度高但性能再次失控

应对：

- 先做骨架，再分批接入动画
- 动画统一挂到可控时间轴与视窗触发器
- 移动端降级

### 风险 2：旧站文案和案例污染迁入新系统

应对：

- 先做内容清单
- 每个页面迁移前做文案审校
- 后台内容模型里明确字段归属

### 风险 3：后台范围膨胀导致首期延期

应对：

- 首期后台只做必要内容管理
- 不做富文本 CMS
- 不做高级权限系统

### 风险 4：视觉还原过程中样式体系失控

应对：

- 先抽 token
- 再做基础组件
- 最后做页面特化样式

## 8. 编码阶段执行铁律

1. 不跳阶段施工。
2. 不先写首页巨型效果再补基础设施。
3. 不先做后台高级功能再补公开站点。
4. 不为了赶进度把数据写死回模板。
5. 不接受“先假提交，后面再接后端”。

## 9. 本文档的作用

从真正开始编码起，本文件就是实施顺序约束。

只要后续开发动作违反本文件的施工顺序或验收标准，就应视为偏离方案，需要先回到方案修正，而不是硬写代码。
